# 秋招跑招聘会，怎么提前知道哪家企业值得聊？

**答：先去看承办方平台的后台数据，别指望公众号推文。**

这是我今年秋招真实做过的一次尝试，把过程写下来，给同样在跑招聘会的同学省点时间。

---

## 一、那天的处境

学校推了一场招聘会，标题写着"上百家企业"，配图是几张模糊的展位照。

我到场之后发现一个问题：**不知道有哪些企业，不知道每家招什么岗。** 只能从第一排开始走，一家一家问"你们招什么"，走到第三排，第一排聊过什么已经忘了。

更麻烦的是，同样叫"软件工程师"的岗位，有的要 Java 后端，有的要 C# 上位机，有的其实是硬件测试。名字完全看不出来，得问，或者看展位上的海报。

后来我才知道：**这些信息平台上有，只是没人告诉你入口在哪。**

---

## 二、一个关键认知：官方推文的数据不可信

那场会的主办方是区人才办，承办方是一家国有人力资源公司。这类活动会有一个独立的线上平台，企业在那里报名、挂岗位。

我上了那个平台，发现两个数字对不上：

- 公众号推文：「集聚上百家园区重点企业」
- 平台后台：报名 92 家，实际挂出岗位 **89 家**

另外 3 家报了名但没发岗位。

这件事让我意识到：**宣传口径和可查数据是两回事**。做任何判断之前，先拿到可以核对的那个数。

---

## 三、我做了什么

简单说：把这场会的所有岗位抓下来，按我的简历打分，做成一个手机上能打勾的清单。

最后的数据是：**89 家企业、375 个岗位、每一个岗位的完整 JD（任职要求 + 岗位职责 + 专业要求 + HR 投递邮箱）。**

然后按我自己的背景（Java 后端 + AI Agent 方向，2027 届本科）打分：

| 分档 | 数量 | 含义 |
|---|---|---|
| 5 分 | 10 个 | 岗位名或 JD 明确要我的技术栈 |
| 4 分 | 8 个 | JD 提到我的方向 |
| 3 分 | 31 个 | 相邻领域 / 测试支持类 |
| 合计对口 | **49 个** | 覆盖 28 家企业 |

89 家企业里，真正值得认真聊的是 28 家。

---

## 四、三个让我意外的发现

### 1. 对口岗位比想象中少得多

我原本以为"375 个岗位"里怎么也有上百个软件岗。实际筛完，纯 Java 后端只有个位数。

原因很简单：**那场会是半导体和高端装备的主场**，大量岗位是工艺、设备、封装、机械、电气。软件岗有，但大多是 C#/C++ 上位机、嵌入式、机器视觉。

这件事的价值在于：**它帮我管理了预期**。我不用在 89 家里焦虑地转，我知道只有 28 家值得去，其中 10 家是重点。

信息透明之后你会更焦虑（选择没那么多），但总比现场被人流推着走、回家才后悔要好。

### 2. 光看岗位名会误判，必须看 JD

我第一版是纯按岗位名匹配的，错得很离谱：

- 「数字后端工程师」→ 我以为是 Java 后端，实际是**芯片物理设计**（APR、floorplan、GDS），完全两个领域
- 「UI/UX 设计实习生」→ JD 里提到"前端"，被判成开发岗
- 「机械测试实习生」→ 被判成软件测试

后来我把每个岗位的 JD 正文也抓下来做匹配，准确率才上来。

**对比数据**：不抓 JD 时对口岗位只有 33 个，抓完 JD 变成 49 个。因为很多岗位就叫"软件工程师"，看名字判不出方向。

### 3. 平台把研发岗挂在"储备干部"类目下

平台自己有岗位分类，我一开始直接用它。后来发现「研发工程师」「光学助理工程师」「PE 助理工程师」全被归到"储备干部/管培生"里。

**分类要以岗位名为准，平台的类目只能当参考。**

---

## 五、现场是怎么用的

我做的是一个网页，长这样：

- **89 家企业全在**，对口的排前面，左边一条色条标等级
- 每家企业左边一个**方框**，投完打勾，整张卡片变绿
- 每家下面一行**备注框**，写"HR 说下周笔试""要英文简历"
- 岗位标签带星的是对口岗，点开能看完整 JD 和投递邮箱
- 底部实时显示「已投 7 / 89 家」

勾选和备注存在浏览器本地，关掉页面再打开还在。

现场我就按对口分从高到低走，5 分的先聊，聊完打勾写备注。走到一半看到某家岗位不错，展开看 JD 决定要不要排队。

---

## 六、如果你想自己做

我把这套东西整理成了一个工具，代码开源在这：

**https://github.com/myzhgjb/jobfair-toolkit**

五条命令跑完一场会：找活动 → 抓企业和岗位 → 补 JD → 按简历打分 → 生成页面。

**但我要说清楚适用范围**：

- 目前只打通了**苏州工业园区**的平台和**江苏高校 91job** 这两条数据线
- 别的城市不一定有公开接口，可能只能靠公众号名单或者学校发的 Excel
- 就算只有 Excel，打分和生成清单这两步仍然能用，只是没有 JD

如果你们城市的招聘会也在类似的平台上（承办方是当地人才中心/人力资源公司），可以自己 F12 看看接口 —— 思路是一样的。

---

## 七、一点感想

秋招最消耗人的不是面试，是**在信息不完整的情况下做决策**。

你不知道哪家值得投，就只能全都投；你不知道岗位要什么，就只能把简历写成万金油；你不知道现场有什么，就只能跟着人流走。

把信息补齐这件事，技术上一点都不难。难的是**大部分人不知道可以这么做**。

希望这篇能帮你省下一个下午。
