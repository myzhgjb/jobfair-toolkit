# 招聘会岗位筛选与路线规划方法论

本文档沉淀完整执行经验，按阶段阅读。

## 一、数据读取

- 输入通常是双 sheet Excel：`企业列表`（展位号/所在专区/单位名称）、`岗位列表`（序号/分区/单位名称/职位名称/简历接收邮箱/职位类别/大类专业/岗位职责/任职职责）。
- 优先使用 `scripts/extract_jobs.py` 完成提取（已处理表头模糊匹配与合并单元格向下填充），输出 JSON 后再筛选，避免反复写一次性脚本。
- 环境：优先用带 openpyxl 的 Python；若 pip 安装失败（沙箱常见），依次尝试系统 Python（常自带 openpyxl）、`pip install -i https://pypi.tuna.tsinghua.edu.cn/simple`。

## 二、岗位筛选（两遍法）

**第一遍：宽关键词初筛**（宁可多不可漏），在 职位名称+职责+专业 上匹配：

```
软件|开发|Java|Python|前端|后端|全栈|测试|运维|IT|信息化|网络|数据|算法|程序|系统|云计算|大数据|人工智能|AI|
嵌入式|硬件|计算机|信创|数字化|网络安全|信息安全|数据库|安卓|iOS|小程序|C\+\+|C#|\.NET|PHP|Golang|JavaScript|
Vue|React|爬虫|MES|ERP|SaaS|平台|工程师|技术员|电子|视觉|GIS|遥感|Layout|FPGA|单片机|机器学习|深度学习
```

**第二遍：全量清单人工复核**。初筛必然大量误报（"制冷系统工程师""电气工程师"也会命中"系统/工程师"）。正确做法：

1. 打印全部岗位紧凑清单（序号|单位|职位|大类），逐行阅读职位名称
2. 仅对职位名称存疑的岗位调出完整职责/任职描述细读
3. 逐条判定 ∈ {纳入, 排除}，排除理由记心里即可

**判定口径参考**（以"计算机/软件开发/IT开发"目标为例）：

- 纳入：软件开发（Web/前端/后端/C++/C#/Java/嵌入式软件）、IT工程师/信息化、网络安全与运维、AI/算法/数据、机器视觉、嵌入式软硬件结合、技术支持（明确要求计算机专业）
- 排除：纯机械/电气自动化/材料化工/土木施工/金融/教培/纯销售（除非软件销售作为兜底档）

**三级优先级**（输出前必须定级）：

| 级别 | 定义 | 建议颜色 |
|---|---|---|
| A类 第一优先 | 岗位名称/职责明确为开发或IT核心岗，专业要求与目标方向高度匹配，应届友好 | 红 #d93025 |
| B类 第二优先 | 技术栈强相关但方向偏（AI落地/视觉/嵌入式硬件/测试/数据），或需一定经验 | 橙 #ef8a17 |
| C类 第三优先 | IT周边（运维实施/驻场/软件销售/GIS应用），作保底 | 灰 #6b7686 |

- 同一家企业多个岗位横跨档位时：以最强岗位定档，其余岗位在表格"同展位可投"中列出。
- 统计口径（参会企业数/岗位条目数/筛出企业数/可投岗位数/三类家数）写进报告头部。

## 三、展位分布图读图（海报常是旋转/压缩的图片）

按顺序执行，每步产物存临时文件：

1. **摆正**：用 PIL `im.rotate(-90, expand=True)` 或 `+90` 试转，读图确认文字方向。
2. **分区定位**：裁剪图例区（一般在一角）并放大 2–3 倍，读出"专区名 ↔ 颜色"对应表。
3. **行列结构**：逐象限裁剪 + 放大（LANCZOS），读出每个色块的展位号范围与行列布局（如"4行×8列，每行展位号从左到右递减"）。
4. **颜色校验**：对每个色块中心采样 RGB（`im.convert('RGB').getpixel((x,y))`），与图例颜色闭环验证，防止"粉色 vs 品红"混淆。淡彩打印色差异小，必须采样不能目测。
5. **出入口**：找"主入口/主出口"红字标签、红箭头方向、上下边缘的黑色闸口条。入口决定路线起点，出口决定终点。
6. **Excel 闭环**：把每个色块的展位号 min–max 与 Excel 各专区展位号范围对照，数量必须相等（各专区范围通常连续无断档），以此兜底纠正读图错误。

## 四、路线规划算法

1. **确定起点终点**：主入口 → 主出口；若有多个出入口，选离高优先级区域近的作起点。
2. **计算每象限的IT企业密度**：优先扫密度最高（通常是目标岗位最多）的象限，HR 精力与自身体力前 90 分钟最好。
3. **象限间**：按"无折返环路"排序——从入口开始，扫完一半场再经中央通道进入另一半场，最终逼近出口。经典布局（十字通道+四象限）的通用解：入口象限 → 同半区相邻象限 → 经通道 → 对面近端象限 → 远端象限 → 出口。
4. **象限内蛇形走位**：按行推进，行内按展位号顺序（与色块编号方向一致），行末就近换行，避免来回横穿。
5. **产物标注**：每个展位一个圆圈（圈内写展位号，颜色=档位），虚线箭头按顺序连线；图例说明三色含义与专区配色。

## 五、交付件（HTML 单文件）

使用 `assets/report_template.html` 为骨架，占位符处填入本次数据。硬性要求：

1. 单 HTML 文件、UTF-8、浅色主题、手机可读（viewport + 自适应表格）
2. 六节结构：头部统计 → SVG 场馆路线图 → 6 段动线文字说明 → A类明细表 → B类明细表 → C类明细表 + 筛选口径说明 → 投递执行建议
3. 表格列：投递顺序 | 展位 | 企业(含专区) | 可投岗位 | 专业/技能要求 | 简历邮箱（无邮箱标"现场投递"）
4. SVG 地图必须包含：四象限色块+展位范围标注、通道、出入口（北门/南门红标+箭头）、全部推荐展位圆圈、按顺序的虚线路径
5. 加 `@media print` 规则，可直接打印带入场
6. 收尾给"执行建议"：时间策略、简历份数、每站5–8分钟话术、现场记录四列法、着装、离场复查

## 六、投递进度清单（配套交付件，与报告一起给）

用 `assets/checklist_template.html` 生成，与路线报告互补：报告管"怎么走"，清单管"投没投"。

1. `SEED` 数组填筛选结果，**按匹配度排序：A类 → B类 → C类，同档内按投递顺序**（用户勾划时从上往下就是投递优先级）
2. `const KEY` 每场招聘会设唯一值，防止 localStorage 数据混存
3. 模板已内置功能，不要删减：勾选=划掉并记时间戳；状态六档（待投递/已投递/已回音/面试中/Offer/不合适，勾选自动把"待投递"推进为"已投递"）；备注栏记 HR/面试时间；**「＋记录其他投递」支持添加任意公司岗位**（网申/内推/现场临时聊的）；按档位与"未完成"筛选；导出/导入 JSON 备份；重置回种子数据
4. 顶栏进度条自动统计：总进度百分比 + 各状态分布
5. 交付时向用户说明：数据存在本机浏览器，换设备/换浏览器用导出导入迁移

## 七、验证与收尾

- 用无头 Chrome 截图验证页面渲染（截图写到 Temp 目录，工作区常被拒绝写入）：
  `chrome.exe --headless --disable-gpu --screenshot=<Temp路径> --window-size=1200,7200 file:///<html路径>`
- 圆圈数 = 筛出企业数，逐区核对；检查虚线路径经过所有圈且无明显交叉混乱。
- 完成后清理中间文件（`_raw_data.json`、裁剪图等），工作区只留交付件。
- 交付后在对话中给出：三级档位统计表、按段的路线顺序清单（文字版，方便复制）、3–5 条现场要点。
