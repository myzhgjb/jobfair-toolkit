# 岗位分类词表与匹配规则

## 核心原则：两级判定，不留"其他"

1. **第一级**：岗位名称关键词（含大量通用职称的业务含义：标准化→工艺、机务→汽车、技术员→制造）
2. **第二级**：名称看不出方向时，**按企业所属行业兜底**（汽车公司的"研发工程师"→ 汽车类，
   材料公司的"研发工程师"→ 材料类，半导体公司的"产品工程师"→ 芯片类）
3. 两级都判不出来的才落「其他 / 未注明」。**正常一场招聘会这个数应低于 1%**，
   如果超过 5%，说明词表或行业映射有缺口，回去补，不要就这样交付。

## 二、四条覆盖顺序的硬规则

1. **教师 / 科目名优先**：名称含 教师/讲师/研究员/博士后/科研/教研/助教/辅导员 → 教育；
   只有"数学""英语"这类科目名的岗位也是教育。
   否则"人工智能学院专任教师"会被 AI 抢走。
2. **先匹配括号前主干，再匹配全名**：`head = 名称.split('（')[0]`。
   "机械工程师（视觉方向）" → 机械；"算法工程师（视觉）" → AI。两边都对。
3. **不要给"助理""专员"这类万能后缀建规则**。它们会把"研发助理"错拉进职能。
   只保留"总经理助理""人事助理""行政助理""销售助理"这种明确职能向的组合。
4. **笼统职称必须靠行业兜底**：研发工程师、产品工程师、系统工程师、助理工程师、技术员、
   技术储干、专业技术岗、职能类……这些词本身没有方向，取决于公司做什么。

## 三、企业行业判定（先看名称强特征）

按顺序执行，命中即返回：

1. `飞机|航空|航天|船舶|轨交|轨道交通|汽车|汽配|机车` → **汽车/轨交/航空**
   （"大飞机江苏太仓研究中心"要归这里，不能因为含"研究中心"归科研）
2. `研究所|研究院|研究中心|科学院`（排除"职业技术"）→ **医院/科研院所**
   （"中国科学院苏州纳米所"要先命中这条，否则会被名字里的"学院"抢到教育）
3. `学校|中学|小学|大学|学院|职业技术|幼儿园|教育|培训` → **教育/学校**
4. 其余按 `名称命中数 × 3 + 简介命中数` 加权打分，取最高：
   材料/化工、半导体/集成电路、生物医药/医疗器械、电子信息/通信、新能源/新材料、
   软件/互联网/AI、高端装备/机器人、金融/投资/保险、国企/城投/物流、建筑/土木
5. 都不中 → 其他/综合

**名称命中要压倒简介命中**：简介里出现"研究院"三个字不代表这家是科研机构。

## 五、背景匹配打分

| 分 | 规则 |
|---|---|
| 5 | 岗位名含用户核心技术词（java / 后端 / 前端 / 全栈 / 服务端 / spring / 微服务） |
| 4 | 软件开发类（软件工程师、嵌入式软件、算法、C++、C#/.NET、Android、数据开发、AI 应用、云原生、测试开发、SDK） |
| 3 | IT / 测试 / 实施 / 技术支持 / 数据 / 售前 |
| 剔除 | ①学历含硕士/博士且不含本科 ②专业不含 计算机/软件/人工智能/数据/物联网/网络/信息安全/电子信息/通信/数学 且非"不限" ③名称含 结构/模具/工艺/机械/硬件/电气/材料/光学/化学/生物/医药/销售/客服/财务/人事/行政/采购/质量/生产/设备/建筑/土木/教师/护士（除非同时含软件/后端/算法等） |

**关键词一定会误伤**，出结果后人工过一遍前 20 条，典型误伤：
- "机器人连接器产品开发工程师" → 机械，不是软件
- "Apps（工艺工程师）" → 工艺，不是 App 开发
- "系统工程师" → 多半是硬件/总体设计
- "研发工程师"（不带方向）→ 走行业兜底，不要硬塞进软件

## 六、技术要点模板

每类给一段职责描述 + 5 个技能点。岗位名命中以下关键词时换用细分变体：

| 变体 | 触发词 | 技能点 |
|---|---|---|
| Agent | agent、智能体、大模型、LLM | Python / LangChain / RAG 与向量库 / Prompt 工程 / Function Calling、MCP |
| 前端 | 前端、web | HTML-CSS-JS / Vue 或 React / 组件化 / Axios / Vite |
| 后端 | 后端、java | Java+Spring Boot / MySQL / Redis / MQ / Docker |
| 数据 | 数据（限 AI 类） | SQL-Hive / Python / ETL / 指标体系 / BI |

这些都**不是官方 JD**，页面里必须标注"技术要求为推断，投递前以现场沟通为准"。
