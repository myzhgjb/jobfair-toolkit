# 招聘会全流程（查会 → 抓 JD → 匹配 → 勾选清单 → 发布）

把「一场招聘会」从网上找信息到现场执行整条链路固化。用户到场前打开手机就知道：**去哪家、投什么岗、投完打勾、随手记备注**。

## 交付物

| # | 产物 | 用途 | 来源 |
|---|------|------|------|
| 1 | `XX参会企业与岗位全库.html` | 全部企业 + 全部岗位 + JD 原文，到场前通读 | `assets/library_template.html` |
| 2 | **`XX投递清单.html`** | 按简历标对口度、可勾选、可写备注、可导出 | `assets/warbook_template.html` |
| 3 | 公网链接 | 手机打开 → 添加到主屏幕 | 发布为应用（sites） |
| 4 | 现场路线报告（有展位图时） | 到馆动线 | `assets/report_template.html` |

> 2 是主力产物，**必须同时具备：勾选框 + 备注输入 + 对口标注 + 导出**。
> 用户的原话通常是「前面留个空格我打勾，旁边留个位置我写标注」。
>

>

## 阶段 0 · 活动识别（最容易翻车）

**先证伪，再结论。** 同校同日可能有两场完全不同的会：

- 学院专场（20–80 家）→ 只在**校就业网 91job**
- 市级/区级综合场（100–300 家）→ 走**市人才办 / 园区引才平台**，91job 查不到

必做的交叉验证：

1. 查 **2 个以上来源**：校就业网、校就业公众号、市/区人才办公众号、本地宝、承办平台。
2. 用**企业数量级**反推：公众号说"300+"但 91job 只有 21 家 → 不是同一场。
3. 用**场地**反推：体育馆（大场）vs 某楼层招聘大厅（小场）。
4. 确认**主办单位**：学院主办 = 专业限定；人才办主办 = 全行业综合。

**宣传口径与实数要分清。** 官方推文常写"上百家企业"，平台可查的往往是"报名 92、挂岗 89"。
页面上用接口实数，并在说明里点出差距——用户会自己核对，别让他发现数字对不上。

## 阶段 1 · 数据获取

优先级：**平台公开接口 > 用户提供的 Excel > 公众号名单 > 现场扫码页**。

### 1.1 苏州工业园区（campus.o-hr.com）

详见 `references/campus-platform-api.md`。三条命令跑完：

```bash
# 1) 找这场会的 fair_key（也可直接在浏览器活动页 URL 里抄）
python scripts/fetch_campus.py discover

# 2) 抓活动 + 全部参会企业 + 岗位（一趟拿全）
python scripts/fetch_campus.py fetch --fair-key <KEY> -o jobfair.json

# 3) 补 JD / 专业 / HR 邮箱（374 条约 4 分钟，断点续传）
python scripts/fetch_campus.py detail --in jobfair.json
```

第 3 步是**必须做的**——列表接口只有岗位名和薪资，JD、专业要求、邮箱全在详情接口里。
不做这一步，页面上就没有"这个岗到底要什么"，价值减半。

### 1.2 江苏高校（91job）

见 `references/sources-and-api.md`，走 `/web/wsjysc/lbxq/` 系列接口，同样有 `getZpgwxq` 能拿 JD。

### 1.3 只有 Excel

跑 `scripts/parse_jobfair.py`，先探结构再解析。典型招聘会 Excel 只有 5–6 列
（单位/简介/岗位/专业/学历/人数），**没有企业规模、没有 JD 正文**。

### 1.4 都没有

只做"活动信息 + 现场攻略"，明确说明拿不到岗位表。**不许编。**

## 阶段 2 · 归类

`scripts/build_page.py` 内置 20 类归类，规则见 `references/taxonomy.md`。

**两级判定，不允许一堆"其他"**：

1. 先看岗位名关键词；
2. 名称看不出方向（研发工程师 / 产品工程师 / 系统工程师 / 技术员 / 技术储干）时，
   **按企业行业兜底**——汽车公司的"研发工程师"归汽车，半导体公司归芯片。

健全标准：**「其他 / 未注明」占比 < 1%**，超过 5% 必须回去补词表。

三个高频陷阱（都踩过）：

- 平台把研发岗挂在「储备干部 / 管培生」类目下 → **岗位名优先于平台类别**
- 「数字后端工程师」是 IC 物理设计，不是 Java 后端
- 「机械测试」「光电载荷定标测试」不是软件测试

## 阶段 3 · 简历对口标注

```bash
python scripts/match_resume.py --jobs jobfair.json --resume resume.txt --report
```

- 简历先转纯文本：docx 用 python-docx，PDF 用 `workbuddy-pdf` 或 pymupdf。
- 脚本自动从简历识别主攻技术簇（后端/前端/AI/嵌入式/硬件/芯片/测试/机械/生物…），
  取命中 ≥3 次的 top2 作主攻。
- 也可手动指定：`--primary backend,ai`。

打分口径（**写进页面，让用户看得见规则**）：

| 分 | 判定 |
|---|---|
| 5 | 岗位名直接命中主攻方向，或 JD 明确要求该技术栈 |
| 4 | JD 提到主攻方向 / 命中次要方向 |
| 3 | 与主攻方向相邻（后端↔测试、嵌入式↔硬件） |
| 2 | 技术岗但方向不同 |
| 0 | 不对口；销售/职能直接 0；**主攻不是芯片时，"数字后端/版图/封装"一律 0** |

两条硬性约束：

- **硕士/博士岗降 2 档**，标注"需冲刺"，不能和本科可投的混在一起排在前面。
- 输出必须带一句**"为什么对口"**，不要只给星级。

结果要直说：如果全场只有 6 个 5 分岗，就告诉用户"这场偏制造业，纯 Java 后端就这几个"，
不要为了好看把 2 分岗提上来。

## 阶段 4 · 生成投递清单

```bash
python scripts/build_page.py --in jobfair.json -o 招聘会-投递清单.html \
  --event-name "2026 秋季双选会" --date "11月20日 14:30-17:00" \
  --place "园区人才市场" --profile "Java 后端 / AI Agent" --degree 本科
```

页面必须含（模板已实现，改动时别删）：

- **企业卡左侧大勾选框**（23px，拇指可点），勾选后整卡变绿
- **企业卡底部备注输入框**（虚线框，placeholder 提示写什么）
- 对口企业置顶 + 左侧色条（5 分蓝 / 4 分绿 / 3 分灰）+ 「对口 N」徽章
- 岗位标签带 ★（≥4 分），点「JD」展开任职要求 / 职责 / 专业 / 投递邮箱
- 筛选：只看对口 / 全部 / 只看没投的 / 只看已投的；学历筛选
- 底部固定条：`已投 X / N 家` + 导出记录 + 复制
- **localStorage 持久化**，key 按场次区分（`build_page.py` 自动生成 `{{SITE_KEY}}`）
- 导出 Markdown（含勾选状态与备注），方便用户发回来
- **默认筛选「全部企业」**，"只看对口"只是一个选项，不能是默认
- **默认筛选「全部企业」**，"只看对口"只是一个选项，不能是默认

**必须向用户说清楚**：勾选和备注存在他自己浏览器的 localStorage，
**刷新不丢，但不会同步给 AI**——这是纯静态页，没有服务器。
要同步就让用户点「导出记录」复制文本发回来。

## 阶段 5 · 发布

用「发布为应用」(sites) 把清单目录发成 https 链接，手机浏览器打开 →「添加到主屏幕」。

目录里只放这一个入口页（`index.html`），全库版作为附带页面同目录即可。
发布后如再改内容，**需要用户当轮明确要求才重新发布**（覆盖线上链接）。

## 质量检查清单

- [ ] 活动信息 ≥2 个来源，企业数量级能对上；页面用接口实数，不跟宣传口径
- [ ] **JD / 专业 / 邮箱抓取成功率 ≥95%**（详情接口逐条抓，失败的单独重试）
- [ ] 页面写明"哪些字段没有"（通常是展位号、场馆平面图）
- [ ] 「其他 / 未注明」分类 < 1%
- [ ] 对口岗与岗位总数一起报给用户，不夸大成"很多"
- [ ] 手机 375px 宽 `scrollWidth === clientWidth`（见下方环境备注）
- [ ] 勾选、备注刷新后仍在（localStorage 生效），导出内容正确
- [ ] 所有 HTML 不依赖外网 CDN，断网可打开
- [ ] 交付目录没有 `.work/`、截图、临时脚本

## 前端两个必须避开的坑

1. **JS 变量名不能和元素 id 同名。**
   写 `let flt='all'` 又给 `<select id="flt">` 绑 `flt.onchange`，绑的是字符串，永远不触发——
   表现为"下拉点了没反应，筛选像坏了"。统一用 `document.getElementById('flt').onchange`。
2. **验证移动端不能看截图宽度。**
   Windows 上 `--window-size=390` 实际视口是 485，截图会被裁切，看着像溢出其实没有。
   用 iframe 固定 390 宽，读 `contentDocument.documentElement.scrollWidth === clientWidth`。
